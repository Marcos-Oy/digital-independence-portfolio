# Project conventions
- Mount mobile floating booking centrally in AppLayout except the diagnostic session; detect all existing booking triggers, exclude the floating trigger itself and triggers inside [data-floating-booking-ignore] (the always-visible sticky landing header), and reuse BOOKING_TRIGGER_CLASS so every booking entry opens the same form. Keep it mounted and toggle opacity/transform with a transition (never conditional render) so it fades in and out, and keep it unclickable and aria-hidden while faded out. It must also stay hidden while any element carrying data-floating-booking-hide (both site and landing footers) is in the viewport, because it would cover footer links such as Política de Privacidad.
- Use shared lateral BrandLogo for navigation and the optimized bundled vertical WebP for home and welcome; the bundled derivative preserves the uploaded logo and loads on Cloudflare without Lovable asset routing.
- Localization uses one Google Translate widget loaded by LanguageSelector after LanguageProvider country detection; set googtrans before initialization and reload on manual changes to avoid restoring Google-mutated React nodes. LanguageProvider maps data-no-translate to notranslate/translate=no; use stable full text instead of typewriter fragments outside Spanish. The browser no longer calls site-translate.
- Translation cache and gateway pause state are service-role-only RLS tables; terminal gateway failures pause all new translation requests until the owner restores access and explicitly clears the pause record.
- Render language flags with LanguageFlag's hosted image pointers resolved against the published Lovable asset origin, not Unicode emojis or deployment-relative asset URLs, so Cloudflare and embedded browsers display flags consistently.
- Call-to-action buttons get their travelling border light from src/lib/ctaEstrella.ts, mounted once by CtaEstrellaEffect in AppLayout; new CTAs must carry .cta-estrella (booking CTAs already do via BOOKING_TRIGGER_CLASS) and must never add overflow-hidden or a second shine overlay, because both clip the light. The floating WhatsApp bubble and the "Volver a Servicios" back link are deliberate exceptions: the bubble uses the incoming-call pulse (.wa-llamada in src/index.css) and the back link is navigation, not a CTA, so neither may carry .cta-estrella. See docs/BOTONES.md.
- Service catalogs (AI_GOVERNANCE_SERVICES, CYBERSECURITY_SERVICES) live in src/views/shared/*ServicesSection.tsx and are rendered by the service page AND its landing page; add new services to the shared component only, never to a single view, so page and landing never drift. Pass the landing's own CTA via the section's cta prop (LandingCtaButton) instead of the service page's booking button.
